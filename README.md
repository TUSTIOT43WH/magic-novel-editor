# 魔境小说编辑器

面向中文长篇小说创作的本地优先编辑器，由 **无敌大番茄** 团队维护。支持纯手动写作，也可以连接作者自己的模型 API，使用剧情续写、图文创作、章节总结、连贯性审校和提问助手。

本仓库为 **clean 初始版本**：首次运行会创建一本“未命名作品”和一个空白章节，不附带原版示例小说、个人书稿、人物设定或模型密钥。

## 项目介绍

围绕“规划 → 写作 → 修改 → 入库 → 继续创作”的流程，集中管理一部小说的正文与创作资料。

### 主要功能

- **多书籍与章节管理**：创建、切换作品，编辑或删除章节，各书的内容与助手会话独立保存。
- **手动写作与 AI 续写**：填写本章剧情意图（Vibe）、正向要求和需要避免的写法，按作品系统提示词生成正文；正文支持流式显示，生成后可修改再入库。
- **图文共同创作**：上传图片并附上文字描述，帮助模型理解人物外观、场景和氛围。支持 PNG、JPEG、WebP，最多 4 张、每张不超过 5 MB，需要所配置模型支持图片输入。
- **大纲、知识库与写作 Skills**：维护卷结构、世界观、地点、规则、道具及写作方法，手动选择本次生成使用的召回资料。
- **人物与关系图**：手动编辑人物档案、状态、颜色标记和关系，支持查看关系网络及批量删除。
- **章节召回与时间线**：入库生成本地总结并更新章节时间线；可点击“AI 优化总结”，使用本章完整正文生成更精确的重点事件、状态变化与伏笔总结。
- **连贯性审校**：检查当前章节之前最多十章的完整正文，支持疑点原文复核；TXT 全书深读作为可选的高消耗模式。
- **提问助手**：支持流式回答、停止生成、修改问题后覆盖回答，以及按书保存的历史会话；可以搜索历史内容、重命名和删除会话。完整工作台与写作台悬浮窗共享状态。

### 提问助手的 Tool Calling

打开“允许查阅本书”后，助手可以按需请求以下只读工具：

| 工具 | 作用 |
| --- | --- |
| `search_chapters` | 检索章节正文与总结 |
| `read_chapter` | 分页读取指定章节 |
| `get_character` | 查询人物档案 |
| `get_relations` | 查询人物关系 |
| `get_timeline` | 查询故事时间线 |
| `search_knowledge` | 检索知识库设定 |
| `get_outline` | 阅读小说大纲 |

运行过程为：**作者提问 → 模型选择工具 → 浏览器查询当前书 → 结果回传模型 → 流式回答**。工具不能修改作品，也不提供联网搜索；页面会展示实际查阅来源。

每次提问最多三轮工具执行、四次模型请求，预取资料与工具结果合计限制为 12000 字符；这不是模型总上下文或 Token 上限。当前章节与知识库工具使用本地关键词检索，不依赖外部向量数据库。

工具调用目前用于兼容 Chat Completions 的接口；本项目的 Responses 适配暂不启用工具，会提示并降级为普通流式问答。工具选择及回答质量取决于作者使用的模型。

## 技术架构

项目采用 TypeScript 编写，包含前端界面与后端接口。

| 层级 | 技术与职责 |
| --- | --- |
| 页面与交互 | React 19、Next.js 16 App Router 结构，主要界面使用普通 CSS |
| 开发与构建 | vinext、Vite 8，通过 Cloudflare Vite 插件提供兼容的运行环境 |
| 模型网关 | `POST /api/generate`，转发作者配置的模型请求，处理文本、图片及流式响应 |
| 助手工具 | 浏览器执行当前书的只读查询；独立助手网关解析工具调用与正文增量 |
| 作品存储 | `GET/PUT /api/workspace`，通过 D1 保存书库 JSON；本地开发使用模拟的 D1 存储 |
| 模型配置 | 本机访问时可在浏览器中记住连接信息，也支持服务端环境变量 |

书籍、章节、知识库、人物、时间线和助手历史保存在书库数据中。当前采用单用户、整库 JSON 保存方式，**没有账号登录、权限控制或多用户隔离**，目前不适合直接作为公开多人服务运行。

## 安装与运行指南

### 1. 准备环境

- Node.js **22.13.0 或更高版本**，并安装 npm。
- 使用克隆方式获取项目时，需要 Git；也可以直接下载仓库 ZIP 后解压。
- 如需 AI 功能，准备兼容接口的 API 地址、API Key 和模型名称；纯手动写作不需要模型密钥。

在终端检查环境：

```bash
node --version
npm --version
```

### 2. 获取项目并安装依赖

```bash
git clone https://github.com/TUSTIOT43WH/magic-novel-editor.git
cd magic-novel-editor
npm install
```

如果使用 ZIP 下载，或已经有本地 clean 文件夹，直接进入包含 `package.json` 的目录执行 `npm install` 即可。

> GitHub 下载内容以已经推送的提交为准；本地尚未上传的更新不会自动出现在远程仓库。

### 3. 启动本地开发服务

```bash
npm run dev
```

打开终端显示的地址，通常为 `http://localhost:3000`。使用期间保持终端运行，结束时按 `Ctrl + C`。

- 不需要另外启动一个后端项目，模型代理与书库接口由本项目一起提供。
- 本地开发的数据库表会在接口读写时自动创建，无需先手动执行迁移。
- 遇到端口占用或已有开发服务的提示，先确认是否已经启动过本项目，不要重复启动。

### 4. 配置模型

推荐在界面中打开 **作品设置 → 模型连接**，填写：

1. **API 地址**：模型服务的接口地址，不是服务商控制台或登录页面。
2. **API Key**：作者自己的模型密钥。
3. **模型名称**：服务商提供的准确模型标识。

点击“启用连接”后再使用 AI 功能。本机地址访问时，连接信息可以保存在当前浏览器中；换浏览器、换端口或清除浏览器数据后可能需要重新配置。

程序支持 Chat Completions 与 Responses 两种接口格式。仅填写域名时会补全 `/v1/chat/completions`，以 `/v1` 结尾时会补全 `/chat/completions`；如果服务商使用不同路径，请填写完整接口地址。**当前未实现 Anthropic 协议，不要填写 `/anthropic` 地址。**

也可以将 `.env.example` 复制为 `.env`，填写服务端配置：

```dotenv
AI_API_URL=填写完整的模型接口地址
AI_API_KEY=填写自己的密钥
AI_MODEL=填写模型名称
```

修改服务端环境变量后重启服务。启用且填写完整的界面配置优先于服务端环境变量。未配置有效模型时，clean 版会提示配置错误，不会返回内置示例小说充当模型结果。

### 5. 开始写作

1. 创建作品，在作品设置中填写写作风格和系统提示词。
2. 根据需要编写大纲、知识库、人物档案和写作 Skills。
3. 在写作台选择章节，手动输入正文，或填写 Vibe 并选择召回资料后生成草稿。
4. 检查并修改正文，点击“入库并更新”。
5. 如本地总结不够准确，点击“AI 优化总结”；需要查询资料或核对情节时，展开提问助手或审校面板。

## 数据与隐私说明

- **模型请求不是完全离线操作。** 点击 AI 生成、总结、审校或提问时，相应正文、图片、问题或检索资料会发送到作者配置的模型 API，可能产生费用。
- 工具检索在本地进行，但查询结果需要回传模型才能用于回答；不会一次性将整本书发送给提问助手。TXT 全书深读会分批发送上传的全文，需要单独确认。
- 上传图片仅按当前书籍、章节暂存在页面内存中，刷新后需要重新选择；仅选择图片不会请求模型。
- 本地开发数据由模拟存储持久化，通常位于项目的 `.wrangler/` 下。升级或移动项目之前，建议先停止服务并备份该目录；请勿将它上传到公共仓库。
- 本机浏览器中保存的模型密钥并非加密保险箱；不要在不可信或共享设备上保存密钥。
- `.env.example` 是可以分享的空白模板；不要提交真实 `.env`、API Key、数据库、私人书稿、图片附件或构建产物。
- 请勿直接把本服务暴露到公网。当前没有用户鉴权，不同访问者可能共享同一份书库数据。
- 界面的“500 万字”是长篇创作的目标容量设定，不是模型单次上下文容量，也不表示当前整库存储已通过同等规模的性能验证。
